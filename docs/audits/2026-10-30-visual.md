# OralCheck visual and structural audit

Audited live https://oralcheck.org on 2026-10-30 with headless Chrome (Playwright, fresh contexts, service workers blocked, `oralcheck:notrack` set, GA/GTM/DoubleClick/Vercel analytics aborted). 390x844 (2x) and 1440x900, light and dark, plus `reduced_motion="reduce"` on a sample, es/pt on a sample, all five result states (low, moderate, elevated, high, urgent-symptom), the email dialog and two kinds of 404.

**Paths.** Every screenshot path below is relative to
`/private/tmp/claude-501/-Users-ianharris-projects-OralCheck/634f3aef-ed1c-43ea-a1d2-663a14401869/scratchpad/ui-audit/`.
`shots-visual/` holds the raw full-page captures. `sheets/` holds contact sheets (the long page cut into side-by-side columns) and zoomed crops, which are easier to read. Mobile pages taller than 8,192 px were re-shot at 1x, because Chrome repeats content past 16,384 device pixels.

**No horizontal overflow** was found at 390 px on any page or locale, and all images loaded. The problems are elsewhere.

---

## The five most important problems

1. **Reduced-motion users get blank pages.** With "Reduce motion" turned on in the OS, every `FadeUp` and `AnimatedLearnCards` block stays at `opacity: 0` permanently. `/learn` renders as an empty page between header and footer. Half of the home page disappears. (H1)
2. **The results gauge contradicts the result.** An *Elevated* result draws a green arc with the needle a quarter of the way round. A *High* result points straight up at the yellow midpoint. The urgent-symptom result points far left into green under a red "See a dentist soon" pill. Moderate and Elevated also share the same amber pill. On a risk tool, this is the most trust-damaging visual on the site. (H4, H5)
3. **Dark mode breaks whole surfaces.** On `/for-clinicians` and `/qr`, white cards keep theme text colours that turn light in dark mode, so the flyer headline, form labels and two buttons go invisible. Separately, teal text sits at 2.8:1 on dark cards across the site. (H2, H3)
4. **Unknown URLs show Next.js's bare default 404**: white page, Arial, no nav, no way home. The branded 404 only appears when a page calls `notFound()` itself. (H6)
5. **Buttons you can't see.** On `/find-care` the Search button and "Use my location" have the same colour as the card behind them, so they read as plain text. The same disabled style hides "Send message" on `/about`. The home hero photo is also blurred by CSS, which makes it look out of focus. (H8, H9)

## High

### H1. Content stays invisible with prefers-reduced-motion. Confirmed
- **Pages:** `/learn` (entire article grid and heading), `/` (features, SEER quote, QR banner, Instagram heading). Both viewports, every locale.
- **Screenshots:** `sheets/learn-m-rm-0.png` (blank page), `sheets/home-m-rm-0.png`. The probe found `opacity < 0.05` on those blocks after a full scroll pass (`metrics-dark.json`, keys `learn-m-rm` and `home-m-rm`).
- **Cause:** `src/components/FadeUp.tsx:13-19` and `src/components/AnimatedLearnCards.tsx:12-21` branch on `useReducedMotion()`. That hook returns `null` during server rendering, so the HTML ships with `style="opacity:0;transform:translateY(28px)"`. On the client, `reduced` becomes `true`, and the component renders a different tree: a plain `<div>`, or `initial={false}` with `whileInView={{}}`. React does not promise to repair attribute mismatches during hydration ([react.dev, hydrateRoot](https://react.dev/reference/react-dom/client/hydrateRoot)), so the server's `opacity:0` stays.
- **Fix:** render the same tree on both server and client, and let Motion handle the preference globally. Motion's `MotionConfig reducedMotion="user"` turns off transform animations but keeps opacity fades ([motion.dev](https://motion.dev/docs/react-motion-config)).
  ```tsx
  // src/app/[locale]/layout.tsx: wrap the providers' children
  import { MotionConfig } from "framer-motion";
  <MotionConfig reducedMotion="user">{children}</MotionConfig>

  // src/components/FadeUp.tsx: no reduced branch
  export default function FadeUp({ children, delay = 0, className }: Props) {
    return (
      <motion.div
        className={className}
        initial={{ opacity: 0, y: 28 }}
        whileInView={{ opacity: 1, y: 0 }}
        viewport={{ once: true, margin: "0px 0px -10% 0px" }}
        transition={{ duration: 0.55, delay, ease: "easeOut" }}
      >
        {children}
      </motion.div>
    );
  }

  // src/components/AnimatedLearnCards.tsx:18-21
  initial={{ opacity: 0, y: 24 }}
  whileInView={{ opacity: 1, y: 0 }}
  ```
  Apply the same pattern anywhere `initial={reduced ? false : …}` is paired with an animation that only fires on view. `HeroSectionPhoto` is safe because it always animates to `opacity: 1`. Also add `<noscript><style>{`[style*="opacity:0"]{opacity:1!important;transform:none!important}`}</style></noscript>` to the layout head so no-JS readers and some crawlers see the content.
- **Related, Confirmed:** without a scroll, half the home page is blank (`sheets/home-m-noscroll-0.png`). Anyone who jumps down the page, or uses an anchor link, sees empty space until the fade catches up. The `-10%` bottom margin above helps a little. The real fix is the same change.

### H2. Dark mode: white cards with theme text are unreadable. Confirmed
- **Pages:** `/for-clinicians` (the "Customize your flyer" form and the whole flyer preview), `/qr` (the card headline, the input placeholder, "Download PNG", "Share link"). Mobile and desktop.
- **Screenshots:** `sheets/for-clinicians-m-dark-0.png`, `sheets/qr-m-dark-0.png`.
- **Cause:** hard-coded `bg-white` combined with `text-ink` and `text-ink-soft`, which become `#e6e2dc` and `#8a8680` in dark mode. Locations: `src/app/[locale]/for-clinicians/PrintableFlyer.tsx:165, 218, 233, 298` and `src/app/[locale]/qr/page.tsx:91, 109, 118, 151, 166`.
- **Fix:** both surfaces are print previews and should stay light. Re-declare the light tokens on them in `src/app/globals.css`:
  ```css
  .surface-light {
    --color-warm: #faf9f6; --color-warm-dim: #f0eee8;
    --color-ink: #2d2d2d;  --color-ink-soft: #6b6b6b;
    --color-brand-soft: #e0f0f0;
    color-scheme: light; color: var(--color-ink);
  }
  ```
  Then add `surface-light` next to each `bg-white` wrapper listed above (PrintableFlyer 165 and 233, qr 109), and change the two qr secondary buttons (151, 166) to `bg-warm text-ink border border-ink/15`.

### H3. Dark mode: teal text fails contrast across the site. Confirmed
- **Pages:** all of them. The wordmark, "Read →", "Find care near you →", "Start screener →", eyebrows ("FOLLOW ALONG"), stat numerals, footer logo, and step-number circles on results.
- **Screenshots:** `sheets/home-m-dark-0.png`, `sheets/results-elevated-m-dark-0.png`.
- **Measured:** `#0d7377` scores 3.36:1 on the dark page and 2.77:1 on dark cards (`#242422`). WCAG 1.4.3 requires 4.5:1 for text this size ([W3C Understanding 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)). The article CSS already fixed this for article links with `#4fb3b6`, which measures 7.6:1 and 6.3:1 (`globals.css`, `--article-link`). The rest of the site never got that fix.
- **Fix:** add the following to `globals.css` under the dark block. Button backgrounds keep `#0d7377`, because white on `#4fb3b6` would fail.
  ```css
  html[data-theme="dark"] .text-brand,
  html[data-theme="dark"] .hover\:text-brand:hover { color: #4fb3b6; }
  html[data-theme="dark"] .hover\:text-brand-dark:hover { color: #7fcbcd; }
  html[data-theme="dark"] .border-brand { border-color: #4fb3b6; }
  ```
  The cleaner long-term version is a `--color-brand-ink` token used for all teal text. The hero headline hard-codes `#0d7377` at `HeroSectionPhoto.tsx:110`. Change it to `var(--color-brand)` so it picks up the override.

### H4. The results gauge disagrees with the tier. Confirmed
- **Page:** `/results`, every band, both viewports.
- **Screenshot:** `sheets/results-bands-top.png` (low, moderate, elevated, high and urgent side by side).
- **What's wrong:** the needle and arc are drawn from `score / 61` (`src/components/RiskGauge.tsx:15-16, 51-52`). The tier cut-offs, though, sit at 4, 13 and 22 (`src/lib/riskEngine.ts:273-297`), so the High tier starts at 38% of the dial. The result:
  - Elevated (16/61) shows a green arc with the needle at about 26%.
  - High (32/61) points straight up at yellow.
  - Urgent symptom (6/61) points far left into green, under a red "See a dentist soon" pill.
  - The gradient (`RiskGauge.tsx:26-30`) runs green to amber to coral by percentage, not by tier.
- **Fix:** export the tier bounds from `riskEngine.ts`, then place the needle inside equal quarter-segments, one per tier:
  ```ts
  // riskEngine.ts
  export const TIER_BOUNDS = { low: [0, 4], moderate: [5, 13], elevated: [14, 22], high: [23, 61] } as const;

  // RiskGauge.tsx
  const SEG = { low: 0, moderate: 1, elevated: 2, high: 3 } as const;
  const [lo, hi] = TIER_BOUNDS[result.tier];
  const within = result.hasUrgentSymptom ? 0.85 : Math.min(1, (result.score - lo) / Math.max(1, hi - lo));
  const pct = (SEG[result.tier] + within) * 25;
  ```
  Swap the single gradient path for four arc segments (each 62.8 units of the 251.3 dasharray) filled with the four tier colours from H5. Fill segments up to the active one, and draw the rest as the faint track.

### H5. Tier pills fail text contrast, and two tiers share one colour. Confirmed
- **Page:** `/results`. The same palette appears on the `/methods` tier tiles.
- **Screenshot:** `sheets/results-bands-top.png`.
- **Measured:** white 14 px semibold text scores 2.70:1 on `#7ba882` (Low), 2.36:1 on `#d4a03c` (Moderate *and* Elevated), and 3.33:1 on `#e8634a` (High). All three fail 1.4.3 at 4.5:1. Moderate and Elevated look identical because `tierColor` is `"mid"` for both (`riskEngine.ts:283-292`).
- **Fix:** add strong fills for the pills in `globals.css` `@theme`. Keep the light ones for arcs and tints.
  ```css
  --color-low-strong: #3d7346;      /* white text 5.62:1 */
  --color-mid-strong: #8a5f12;      /* 5.64:1 */
  --color-elevated-strong: #a8541c; /* 5.32:1 */
  --color-high-strong: #b5432d;     /* 5.52:1 */
  ```
  Give the elevated tier its own `tierColor: "elevated"` in `riskEngine.ts`. Map pill backgrounds in `RiskGauge.tsx:8-13, 75-78` to the `-strong` tokens.
- **Same failure on the home hero CTA:** "Check your risk" puts white 14 px text on `#e8634a` at 3.33:1 (`HeroSectionPhoto.tsx:158-163`). Use `var(--color-accent-dark)` (`#c84d35`, 4.6:1) and `fontSize: "1rem"`, or adopt the shared button from M1.

### H6. Unmatched URLs render Next.js's unstyled default 404. Confirmed
- **Pages:** `/this-page-does-not-exist`, `/es/no-existe`, and any unknown path not under a matched route. Both viewports. In dark mode, the bottom of the viewport turns black.
- **Screenshots:** `shots-visual/this-page-does-not-exist-m.png`, `sheets/nf.png`. On the left of `sheets/nf.png` is `/learn/not-a-real-article`, which does reach the branded page. On the right is `/es/no-existe`, which does not.
- **Cause:** `src/app/[locale]/not-found.tsx` only renders when a page inside `[locale]` calls `notFound()`. There is no catch-all route and no root `not-found`. next-intl documents a catch-all that calls `notFound()` as the way to fix this ([next-intl: error files](https://next-intl.dev/docs/environments/error-files)).
- **Fix:**
  ```tsx
  // src/app/[locale]/[...rest]/page.tsx
  import { notFound } from "next/navigation";
  export default function CatchAll() { notFound(); }
  ```
  Also add `src/app/not-found.tsx` that renders a minimal branded page for requests with no locale. The existing `not-found.tsx` hard-codes English and has an em dash in its copy, so pass it to the copy audit and move its strings into `messages/*.json`.

### H7. The /for-clinicians flyer preview is clipped and crushed at 390 px. Confirmed
- **Page:** `/for-clinicians`, mobile, every locale.
- **Screenshots:** `sheets/zoom-flyer.png`, `sheets/for-clinicians-m-0.png`.

- **Fix:** this is a print preview, so scale a faithful letter-width page rather than reflowing it:

  ```tsx
  <div ref={wrapRef} className="w-full" style={{ height: flyerH * scale }}>
    <div className="origin-top-left" style={{ width: 816, transform: `scale(${scale})` }}>
      {/* existing flyer, with w-full max-w-[800px] removed */}
    </div>
  </div>
  ```
  Use `scale = Math.min(1, wrapWidth / 816)`. Keep the `print:` styles on the inner node so printing is unchanged.

### H8. The home hero photo is blurred by CSS and upscaled. Confirmed
- **Page:** `/`, desktop (the photo is hidden below `lg`).
- **Screenshot:** `sheets/home-d-hero.png`.
- **Cause:** `HeroSectionPhoto.tsx:54` applies `filter: blur(2px)`. The source is a 1200x800 Unsplash crop (`:8-9`) stretched with `object-fit: cover` into a box about 780x1080 px, then scaled again by 1.04 (`:250`). The whole image looks out of focus, which reads as a broken asset rather than a style choice. A tightly cropped stock smile also leans "cosmetic dentistry ad" rather than "clinical screening tool".
- **Fix:** remove `blur(2px)` from `imgFilter` and request a portrait crop at the size it is displayed: `?w=1100&h=1500&fit=crop&crop=faces&auto=format&q=80`. Better still, switch to `next/image` with `sizes="(min-width:1024px) 54vw, 0px"`. Longer term, swap it for an image in the house illustration style. The `/learn/signs` diagrams and self-exam photos are closer to the site's tone.

### H9. Buttons that are invisible against their card. Confirmed
- **Pages:** `/find-care` (Search before typing, and "Use my location" at all times), `/about` ("Send message" before typing). Mobile and desktop.
- **Screenshots:** `sheets/zoom-findcare-search.png`, `sheets/about-m-0.png` (middle column).
- **Cause:**
  - The search card is `bg-warm-dim` (`find-care/page.tsx:181`).
  - Search uses `disabled:bg-warm-dim` (`:193`).
  - "Use my location" is `bg-warm-dim … border-warm-dim` (`:201`).

### M5. "Card soup": every section is the same grey box. Confirmed
- **Pages:** site-wide. There are 61 `bg-warm-dim … rounded-2xl` boxes in `src/`. Definition, every cancer type, every risk factor, every FAQ, sources, disclaimers, forms and result sections are all the same grey rounded rectangle at the same radius and padding.
- **Screenshots:** `sheets/learn_oral-cancer-m-0.png`, `sheets/results-high-m-0.png`, `sheets/about-m-0.png`.
- **Why it matters:** cards are meant for browsable, linkable chunks. Design systems that build on NN/g's guidance advise against cards for sequential reading and dense information ([NIHR](https://design-system.nihr.ac.uk/component/card), [UK Parliament](https://designsystem.parliament.uk/components/cards/), [European Commission](https://ec.europa.eu/component-library/ec/components/card/usage)). Uniform boxes around everything is a large part of what makes the site look templated.
- **Fix:** keep `bg-warm-dim rounded-2xl` for (a) link cards and (b) one emphasised callout per page. Turn explanatory sections into plain text under an `h2` separated by `border-t border-ink/10 pt-8 mt-12`. Turn FAQ accordions into a hairline `divide-y divide-ink/10` list with no fill.
